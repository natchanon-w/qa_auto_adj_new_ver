========================================================
  QA GUIDE: merge_step - Test Data Generator & Uploader
========================================================

OVERVIEW
--------
This tool generates encrypted CSV test data for the
Void ITMX Billers reconcile pipeline, then uploads it to S3.
It also produces SQL to seed matching rows in both
bill_payment_transaction and bill_payment_transaction_void
so the void flow can be exercised end-to-end.

REQUIREMENTS
------------
- Go 1.21+  (run: go version)
- AWS CLI   (run: aws --version)
- AWS profile configured in ~/.aws/credentials
- public.pgp and private.pgp must be present in this folder


CONFIGURATION
-------------
config.json holds one entry per S3 environment under
"environments", plus "active_env" to pick which one is used
by generate/finalize/upload:

  {
    "active_env": "sit",
    "environments": {
      "sit": {
        "bucket":      "vb-payment-sit-s3-reconcile",
        "base_path":   "dp/adjustment/void/2026-01-10/",
        "aws_profile": "s3_sit_vb"
      },
      "uat": {
        "bucket":      "cb-core-bank-th-uat-s3-payment-reconcile",
        "base_path":   "dp/adjustment/void/2026-01-20/",
        "aws_profile": "s3-cb-uat-th-dpp"
      }
    }
  }

  - active_env  : name of the environment to use (must match a
                  key under "environments", e.g. "sit" or "uat")
  - bucket      : S3 bucket name
  - base_path   : S3 folder path (the date in the path sets the CSV
                  filename date AND backdates every generated
                  timestamp field to that date)
  - aws_profile : AWS CLI profile name from ~/.aws/credentials

To switch environments (e.g. sit → uat), just change
"active_env" — no code changes needed. You can add more
environments by adding more entries under "environments".


STEPS
-----

STEP 1 — Generate test data
  Command:
    go run . generate <number-of-records>

  Example (generate 5 records):
    go run . generate 5

  What it does:
    - Builds CSV rows for the reconcile file
    - Builds a matching bill_payment_transaction row per record
    - Builds a linked bill_payment_transaction_void row per record
      (status defaults to FAILED), joined via retrieval_ref_no
    - All record date/time fields are backdated to a random time
      on the date taken from base_path in config.json

  Output:
    - work/<timestamp>/raw.csv      (editable plain CSV)
    - work/<timestamp>/state.json   (internal state, do not edit)

  Tip: You can open and edit raw.csv before running finalize
       if you need to adjust specific field values.


STEP 2 — Finalize (encrypt + verify)
  Command:
    go run . finalize

  What it does:
    - Reads raw.csv from the latest work folder
    - Encrypts CSV using public.pgp
    - Verifies the encryption using private.pgp (SHA256 checksum)
    - Generates control JSON and SQL insert/delete scripts for
      both bill_payment_transaction and bill_payment_transaction_void

  Output (inside work/<timestamp>/output/):
    - VOID_ITMX_BILLERS_RECONCILE_UNMATCHED_<date>.csv.encrypted
    - reconcile-lending-void_itmx_billers-<uuid>.json
    - insert_void_transactions.sql
        Wrapped in a single BEGIN;/COMMIT; transaction and contains
        2 sub-scripts, stacked back to back — run the whole file:
          1) INSERT statements for bill_payment_transaction
          2) INSERT statements for bill_payment_transaction_void
             (transaction_id is resolved via a subquery against
             bill_payment_transaction's retrieval_ref_no, so if
             part 1 fails or is skipped, the transaction aborts
             instead of leaving void rows with bad data)
    - delete_void_transactions.sql
        Also wrapped in BEGIN;/COMMIT; and contains 2 sub-scripts,
        in this order (void first, since it references the main
        table's retrieval_ref_no):
          1) DELETE statements for bill_payment_transaction_void
             (by retrieval_ref_no)
          2) DELETE statements for bill_payment_transaction
             (by ref_id)


STEP 3 — Upload to S3
  Command:
    go run . upload

  What it does:
    - Cleans all existing files in the S3 base_path folder
    - Uploads .encrypted and .json files to S3

  Target:
    s3://<bucket>/<base_path>/


FULL EXAMPLE
------------
  go run . generate 5
  go run . finalize
  go run . upload


WORKING WITH A SPECIFIC FOLDER
-------------------------------
If you need to finalize or upload a specific work folder
(not the latest), pass the folder path as an argument:

  go run . finalize work/20260617_131102
  go run . upload   work/20260617_131102


NOTES
-----
- The date in the encrypted CSV filename, and every backdated
  timestamp field in the SQL rows, is taken from base_path in
  config.json, NOT from today's date.

  Example:
    config.json base_path : "dp/adjustment/void/2026-01-10/"
    Output filename       : VOID_ITMX_BILLERS_RECONCILE_UNMATCHED_20260110.csv.encrypted

  To change the filename/backdate date, update the date segment
  in base_path.

- Each time you run upload, the S3 folder is wiped first,
  so only the latest generated files will be present.

- SQL files seed/clean up test records in both the
  bill_payment_transaction and bill_payment_transaction_void
  tables (run manually in DB as needed). Each generated void
  row links back to its main transaction row via
  retrieval_ref_no and defaults status to FAILED.

- insert_void_transactions.sql and delete_void_transactions.sql
  each bundle 2 sub-scripts (one per table) in a single file —
  when running manually, make sure to execute both parts, not
  just the first block.
