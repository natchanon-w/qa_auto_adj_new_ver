========================================================
  QA GUIDE: merge_step - Test Data Generator & Uploader
========================================================

OVERVIEW
--------
This tool generates encrypted CSV test data for the loan
Repayment reconcile pipeline — REPAYMENT_MANUAL_DDR (same-bank)
and/or REPAY_CROSS_BANK (crossbank) unmatched records — then
uploads it to S3.

REQUIREMENTS
------------
- Go 1.21+  (run: go version)
- AWS CLI   (run: aws --version)
- AWS profile configured in ~/.aws/credentials
- public.pgp and private.pgp must be present in this folder


CONFIGURATION
-------------
config.json holds one entry per S3 environment under
"environments", plus "active_env" to pick which one is used
by generate/finalize/upload, and "generate_mode" to pick which
dataset(s) `generate` produces:

  {
    "active_env": "sit",
    "generate_mode": "both",
    "environments": {
      "sit": {
        "bucket":         "vb-payment-sit-s3-reconcile",
        "base_path":      "dp/adjustment/repayment/2026-01-08/",
        "aws_profile":    "s3-sit-vb",
        "encryption_key": "..."
      },
      "uat": {
        "bucket":         "cb-core-bank-th-uat-s3-payment-reconcile",
        "base_path":      "dp/adjustment/repayment/2026-01-09/",
        "aws_profile":    "s3-cb-uat-th-dpp",
        "encryption_key": "..."
      }
    }
  }

  - active_env     : name of the environment to use (must match a
                      key under "environments", e.g. "sit" or "uat")
  - generate_mode  : which dataset(s) `generate` writes — one of:
                        "repayment"  : REPAY_MANUAL_DDR only (same-bank repayment)
                        "crossbank"  : REPAY_CROSS_BANK only (crossbank repayment)
                        "both"       : both, in the same run
                      Omitting this key defaults to "repayment" (old config.json
                      files keep working unchanged).
  - bucket         : S3 bucket name
  - base_path      : S3 folder path (the date in the path sets the CSV filename date)
  - aws_profile    : AWS CLI profile name from ~/.aws/credentials
  - encryption_key : base64 AES-256 key, MUST match the crypto.encryption_key of the
                     environment you're inserting into (e.g. SIT/UAT). This encrypts
                     the whitelisted PII columns (from_acct_no, from_account_name_en,
                     to_acct_no, etc.) with the exact same AES-256-GCM scheme
                     savedb-consumer uses, so it can decrypt them on read. Get this
                     value from whoever manages that environment's secrets — never
                     put a real PRD key in this file.

To switch environments (e.g. sit → uat), add a new entry
under "environments" with that env's bucket/base_path/
aws_profile/encryption_key, then set "active_env" to its
name — no code changes needed.


CROSSBANK REPAYMENT (REPAY_CROSS_BANK)
---------------------------------------
Set "generate_mode": "crossbank" (or "both") to also generate a
REPAY_CROSS_BANK_RECONCILE_UNMATCHED_<date>.csv dataset alongside
(or instead of) the regular REPAYMENT_MANUAL_DDR one. It carries
one extra column, cbpay_status, and its own decision-matrix test
cases (see crossbankCases in generate.go — confirmed by business
2026-08-13 against payment-bulk-adj-repayment-processor's
REPAY_CROSS_BANK matrix). Both datasets insert into the same
repayment_transactions table, so `finalize` still emits one combined
insert/delete SQL script covering every row generated this run —
each row/statement carries a "-- dataset: repayment|crossbank |
ref_id: <ref>" comment (see STEP 2 below) so which dataset a given
row belongs to is identifiable at a glance.


STEPS
-----

STEP 1 — Generate test data
  Command:
    go run . generate <number-of-records> [mode]

  mode (optional): "repayment" | "crossbank" | "both"
    Overrides config.json's "generate_mode" for this run only —
    config.json is not modified.

    If you omit it, the tool prompts interactively instead of
    silently using config.json's generate_mode:

      Select generate_mode:
        1) repayment
        2) crossbank
        3) both  (config.json default)
      Enter choice [1-3] (blank = both):

    Press Enter on a blank line to accept config.json's current
    generate_mode, or type 1/2/3 or the mode name.

  Example (prompted interactively):
    go run . generate 5

  Example (generate 5 crossbank records, no prompt):
    go run . generate 5 crossbank

  Output (which raw_*.csv file(s) appear depends on the mode in effect):
    - work/<timestamp>/raw_repayment.csv  (editable plain CSV, if generate_mode includes repayment)
    - work/<timestamp>/raw_crossbank.csv  (editable plain CSV, if generate_mode includes crossbank)
    - work/<timestamp>/state.json         (internal state, do not edit)

  Tip: You can open and edit the raw_*.csv file(s) before running
       finalize if you need to adjust specific field values.


STEP 2 — Finalize (encrypt + verify)
  Command:
    go run . finalize

  What it does (once per dataset present in state.json):
    - Reads raw_repayment.csv and/or raw_crossbank.csv from the latest work folder
    - Encrypts each CSV using public.pgp
    - Verifies the encryption using private.pgp (SHA256 checksum)
    - Generates one control JSON per dataset, plus one combined SQL
      insert/delete script covering every row generated this run.
      Each row (insert) / statement (delete) is preceded by a
      "-- dataset: repayment|crossbank | ref_id: <ref>" comment, so
      rows from either dataset are identifiable — and traceable back
      to the matching CSV row via ref_id — without splitting files.

  Output (inside work/<timestamp>/output/):
    - REPAY_MANUAL_DDR_RECONCILE_UNMATCHED_<date>.csv.encrypted              (if repayment)
    - reconcile-lending-repayment_manual_ddr_unmatched-<32hex>.json          (if repayment)
    - REPAY_CROSS_BANK_RECONCILE_UNMATCHED_<date>.csv.encrypted             (if crossbank)
    - reconcile-lending-repayment_cross_bank_unmatched-<32hex>.json          (if crossbank)
    - insert_repayment_transactions.sql   (all rows generated this run)
    - delete_repayment_transactions.sql


STEP 3 — Upload to S3
  Command:
    go run . upload

  What it does:
    - Cleans all existing files in the S3 base_path folder
    - Uploads .encrypted and .json files to S3

  Target:
    s3://<bucket>/<base_path>/


FULL EXAMPLE
------------
  go run . generate 5
  go run . finalize
  go run . upload


WORKING WITH A SPECIFIC FOLDER
-------------------------------
If you need to finalize or upload a specific work folder
(not the latest), pass the folder path as an argument:

  go run . finalize work/20260617_131102
  go run . upload   work/20260617_131102


NOTES
-----
- The date in the encrypted CSV filename is taken from
  base_path in config.json, NOT from today's date.

  Example:
    config.json base_path : "dp/adjustment/repayment/2026-01-11/"
    Output filename        : REPAYMENT_MANUAL_DDR_RECONCILE_UNMATCHED_20260111.csv.encrypted
                              REPAY_CROSS_BANK_RECONCILE_UNMATCHED_20260111.csv.encrypted

  To change the filename date, update the date segment in base_path.

- Each time you run upload, the S3 folder is wiped first,
  so only the latest generated files will be present.

- SQL files are for inserting/deleting test records in the
  repayment_transactions table (run manually in DB as needed).
